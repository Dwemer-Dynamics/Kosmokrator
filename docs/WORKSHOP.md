# Preparing a mod for the Steam Workshop

Kosmokrator prepares a folder that the Dominions 6 Workshop uploader accepts. It can also copy that folder into your
local `mods` directory. **It never uploads, publishes or contacts Steam.** The upload is done by Dominions 6 itself.
Kosmokrator holds no Steam login and uses no SteamCMD or Workshop API.

The rules below come from Sombre's creator guide,
<https://steamcommunity.com/sharedfiles/filedetails/?id=3141394816>:

- Everything inside the mod folder is uploaded.
- The folder needs `dom6ws.txt` containing only `Visibility = "Public"`.
- The preview image is `banner.png`, 256x256 pixels.
- Upload from the game: open **Mods**, right-click the mod's **local** entry, then choose **Upload to Steam
  Workshop**.
- After an upload the game writes `dom6ws_pfid` into the mod folder. Keep it: deleting it makes the next upload a
  new Workshop item instead of an update.
- Each update resets the Workshop description to "Dominions 6 mod". Re-enter it on the Workshop page after updating.

The game loads mods from `mods/<slug>/<slug>.dm`, which is the layout Kosmokrator exports.

## In the browser

Click **Export mod** in the project heading, on any section, then use **Steam Workshop folder**. See
[WEB-BROWSER.md](WEB-BROWSER.md#steam-workshop-folder) for each step.

## What the prepared folder contains

`POST /api/projects/<slug>/workshop/prepare` takes `{expected_sha256, export_id, visibility}`, plus an optional
`banner_asset` that must name an image already in the export. The server holds the project lock and checks:

- the saved `.dm` still has `expected_sha256` (else 409 `sha_mismatch`), and the export was built from that revision
  (else 409 `stale_export`);
- the export's archive and every file still match its manifest hashes, with no extra or missing files (else 409
  `export_changed`);
- `visibility` is a documented value (else 400 `bad_visibility`). Only `Public` is accepted. Private, friends-only
  and unlisted are set on the Workshop item page after uploading, as the guide describes;
- the export does not already contain Workshop control files (`dom6ws.txt` with a different value, or
  `dom6ws_pfid`).

It then writes, under `<project>/exports/workshop/`:

```
<slug>-ws-<UTC stamp>-<8 hex>/<slug>/       content folder: the exported .dm and assets, byte for byte,
                                            plus dom6ws.txt and banner.png - nothing else
<slug>-ws-<UTC stamp>-<8 hex>.zip           the same content folder as a ZIP
<slug>-ws-<UTC stamp>-<8 hex>.manifest.json hashes, source export, banner method, steps (outside the content folder)
```

Names are generated by the server and never overwritten. Art sources, logs, caches, manifests and project state are
never added to the content folder. The regular export ZIP is not changed.

**banner.png** reuses the mod's own `#icon` image (TGA or 8-bit RGBA PNG). An image up to 256x256 is centred unscaled
on a transparent 256x256 canvas, so its pixels and aspect ratio are kept. A larger image is reduced by
nearest-neighbour sampling, with one scale for both axes. This is mechanical packaging; no artwork is generated. If
the mod already ships a 256x256 `banner.png`, it is used unchanged.

## Compatibility check (installation preflight)

`GET /api/projects/<slug>/preflight?target=<export id or Workshop id>` (browser: **Check compatibility** on the Export
and Workshop panels; agents: `author_state` kind `preflight:<id>`) re-verifies that exact bundle against its manifest
and compares its numbered definitions with the `.dm` files in the configured mods folder (top level and one folder
down, bounded by file count, per-file and total bytes; links are never followed). It writes nothing and runs only
when asked.

- `#new...` reusing an installed ID, and two custom nations 150+ (`#selectnation 150+` creates a nation), are
  errors. Reordering mods never fixes them; remap with `allocate_ids` or move the other mod out yourself.
- Both mods selecting an existing identity (for example a nation below 150), or patching an ID only an undeclared
  installed mod creates, are review warnings. A byte-identical declared dependency makes a patch informational.
- Every finding names the file, line, command and ID on both sides. Load order is reported as unknown; installed does
  not mean enabled; Workshop subscriptions outside the configured folder are not scanned.
- This project's own install is skipped only when it is identical or every file is one it installed. An edited or
  foreign copy is an error and is scanned like any other mod.
- Unreadable entries, links or a reached limit make the result `incomplete`.

The result has a `fingerprint` over the manifest, bundle `.dm` hashes, every scanned file's path, hash and size, scan
completeness, destination ownership and declared dependency hashes. Status is `pass`, `review`, `blocked` or
`incomplete`.

## Optional local install

`POST /api/projects/<slug>/workshop/<id>/install` takes `{expected_sha256, expected_preflight}`, plus
`acknowledge_review` (the same fingerprint) when the check has review warnings. Under the project lock and right
before its first write, the server recomputes the preflight. It refuses with `preflight_required`, `preflight_stale`,
`preflight_blocked` or `preflight_review` and writes nothing. Files can still change after that recheck; it is not a
cross-process atomic guarantee. The destination is
`<mods>/<slug>`, where `<mods>` is set when the server starts:

- `KOSMOKRATOR_DOMINIONS_MODS=<absolute path>`; an empty value or `off` turns local install off;
- otherwise `%APPDATA%\Dominions6\mods`, if it exists.

The browser can never name a path. Before copying, the server re-hashes the prepared folder against its manifest
(409 `workshop_changed`) and checks the revision again. Links and junctions are refused. Then:

| Destination | Result |
|---|---|
| missing | created and filled (`installed`) |
| identical to the prepared files | nothing is written (`unchanged`) |
| every file is one this project installed | changed files are replaced and files the new revision dropped are removed (`updated`) |
| anything else (another copy, edited files, extra files) | refused with 409 `install_conflict`; nothing is changed |

`dom6ws_pfid` is never written, moved or removed. Kosmokrator records its installs in
`<project>/.kosmokrator/workshop/installs.json`, outside the mod folder. It never renames an existing folder,
because a renamed copy would upload as a second Workshop item. To replace a folder you installed by hand, back it
up, keep its `dom6ws_pfid` if the mod is already published, and copy the prepared files yourself.

## Upload (manual, in the game)

1. Start Dominions 6 from Steam. The browser's **Launch Dominions 6 in Steam** link opens `steam://run/2511500` when
   you click it.
2. Open **Mods**, right-click the mod's **local** entry, and choose **Upload to Steam Workshop**.
3. On the Workshop page, set the title, description and visibility.
4. Keep `dom6ws_pfid` for future updates.

Static validation does not prove that the mod loads, plays or is balanced. Test it in Dominions 6 before you upload.
